Comparative Fashion Product Recommendation Using Collaborative Filtering and Matrix Factorization

Progress report · 2026-10-22 · Initial offline experiment

The project recommends fashion products from previous user preferences and compares algorithms under the same evaluation conditions. SVD obtained the highest test NDCG@10 in this pilot. These measurements support a reproducible progress submission; wider validation and a user-facing prototype remain future work.

Problem and objectives

Online fashion catalogs contain many products. The research question is whether personalized behavioral models recover later highly rated products more effectively than recommending the same popular products to everyone. The first objectives are dataset preparation, reproducible baselines, an algorithm comparison, and measured ranking quality.

Dataset and preparation

Downloaded the Amazon 2014 Clothing, Shoes and Jewelry 5-core file from the official Amazon dataset page. The local file contains 278,677 reviews, 39,387 users and 23,033 products. User ID, product ID, rating and timestamp are used in this experiment.

The source covers 2003-03-29 to 2014-07-23 in the downloaded category. It is historical research data. The source page does not specify a standalone permissive data license, so it should be described as publicly available research data.

Retain each user–product pair's earliest review, producing 278,677 unique pairs. Training contains 222,413 reviews, validation 28,185, and test 28,079. The time boundaries are 2014-03-20 and 2014-05-18. Positive training interactions total 177,836.

Implemented algorithms

  • Random: reproducible random ranking to provide a basic reference.
  • Popularity: rank products by the number of positive training reviews.
  • ItemKNN: cosine similarity between product interaction columns, retaining 100 neighbors per product. Score products from the user's positive history. A tiny popularity term breaks equal scores.
  • SVD: 64-component truncated singular value decomposition of the binary interaction matrix, with seven iterations and seed 42.
  • Blend: normalize ItemKNN and popularity scores and combine them. This is a behavioral–popularity blend; product content is planned for a later hybrid.

Experimental method

Global chronological split; ratings ≥4 are positive preferences. Models rank the full training-positive catalog, excluding products already reviewed. The blend weight was selected on 1,000 validation users. All models use the same frozen training window.

Evaluate users with at least three training reviews and at least one positive held-out product in the training-positive catalog. The pilot samples at most 1,000 validation users and 3,000 test users with seed 42; 6,700 test users satisfy the eligibility rules. All algorithms are evaluated on the same selected users and targets.

Of 21,802 positive test events, 15,229 have a user and item present in training. Further history and sampling rules determine the evaluated users. This warm-start comparison does not assess new-user or new-item performance.

Metrics are averaged per user. Precision measures the fraction of ten recommendations that are relevant; recall measures the fraction of relevant held-out products recovered; NDCG rewards relevant products near the top; MRR measures the position of the first relevant product; coverage is the fraction of candidate products recommended to at least one evaluated user.

The validation search tried ItemKNN weights 0.25, 0.50, and 0.75; the selected weight was 0.50. Model and popularity features are fitted only on training interactions. For test recommendations, validation-period reviews are also excluded as previously seen products, but do not update model features.

SVD achieved NDCG@10 of 0.00586, compared with 0.00327 for popularity (+79.5% relative difference). This is a ranking metric, not a classification accuracy percentage.

For the prespecified Blend-versus-Popularity comparison, mean NDCG difference is 0.00127. A paired bootstrap over test users with 2,000 resamples gives a 95% interval of [-0.00027, 0.00284]. The interval includes zero; this experiment does not establish a positive difference. It does not establish that the blend is best on other datasets or time periods.

Progress and limitations

Completed: source research, dataset download and checksum, preprocessing, chronological splits, five ranking approaches, validation-only blend selection, test evaluation, metric export, sample recommendations, and reproducible charts.

Pending: product metadata and visual recommendations, a content-based model, broader hyperparameter experiments, cold-start evaluation, repeated time-window validation, and an interactive demonstration. The current results use product IDs because product names and images have not been downloaded.

Reviews are proxies for preferences rather than purchase logs, and products without reviews are not verified negative examples. The historical 5-core subset favors active users and reviewed items. Low ranking scores on a large catalog are possible and should be reported honestly. Results from other repositories cannot be compared directly unless data, candidate sets, and split protocols match.

Related work and available implementations

  • FashoReco: an existing H&M student project for studying project structure and recommendation workflows; check its license before copying code.
  • RecBole: a reusable framework for expanding the algorithm comparison.
  • implicit: collaborative filtering implementations suitable for adding ALS and BPR.
  • A Review of Modern Fashion Recommender Systems: background for the literature review and the distinction between product, outfit, and size recommendation.

For a later large-scale experiment, consider Amazon Reviews 2023. The H&M competition is another relevant source, subject to its access rules and noncommercial/academic use conditions; it was not downloaded for this pilot.

Next milestones

  1. Expand the comparison: add implicit ALS or BPR and test several factor counts and neighborhood sizes using validation data.
  2. Add fashion content: obtain the matching product metadata, filter to this catalog, and compare title/category TF-IDF against collaborative models. Then test a content–collaborative hybrid. Do not use held-out review text as product features.
  3. Strengthen the evidence: run all eligible users, repeat across global time cutoffs, report uncertainty, and evaluate new users/items separately. Reserve a new untouched test window for later model development.
  4. Build the demonstration: add a small interface with product names and images after obtaining suitable metadata. Explain recommendations and show the selected user's history.
  5. Finalize the submission: add student/institution details, objectives, related work, methodology, the measured comparison, limitations, and the next milestone. Export this report to PDF through browser printing.

Reproducibility and verification

Results were generated locally, rather than copied from another project. Run details and package versions are in results/run.json; commands are in README.md. The benchmark asserts strict time ordering, disjoint relevant and seen products, ten unique unseen recommendations, finite selected scores, and metric bounds. Ranking helpers were checked against hand-calculated metric examples.
